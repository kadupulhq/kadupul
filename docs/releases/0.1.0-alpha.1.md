# Kadupul 0.1.0-alpha.1 release preparation

This is a preview for isolated evaluation. It is not a production-supported
release and does not provide a supported production migration path. It is the
first release numbered in Kadupul's own 0.x series (see `VERSIONING.md`) and
supersedes `v1.3.0-alpha.1`. Semantic Versioning orders `1.3.0-alpha.1` above
`0.1.0-alpha.1`, so tools that compare versions will treat this release as
older; install it explicitly by tag.

The legacy application/schema compatibility marker in `include/cacti_version`
is separate from the package tag. It is 1.2.39 in this release (1.2.35 in
`v1.3.0-alpha.1`).

## Acceptance before tagging

- Merge the versioning change (#1461) and this release preparation with
  current-head CI and the repository review policy, or an explicitly recorded
  maintainer exception.
- Run `python3 tools/changelog.py release 0.1.0-alpha.1` in the last PR merged
  before the tag. It moves the `[Unreleased]` entries and the `changelog.d/`
  fragments into a `[0.1.0-alpha.1]` section with the release date, opens a new
  empty `[Unreleased]` above it and deletes the fragments.
- Confirm the selected tag commit is on main, contains that versioned
  changelog, and passes main's current-head checks, including the Sonar
  Quality Gate, the offline bundle build, the upgrade/rollback rehearsal and
  release container acceptance.
- Record the exact source SHA and CI run URLs below. Tag that verified SHA as
  `v0.1.0-alpha.1`; do not tag an unreviewed worktree head.

The tag invokes the release workflow. It creates a draft, publishes the signed
container and attaches the dependency-complete offline archive with its
checksum and Sigstore bundle. Only successful verification of both archive and
container provenance makes the draft public. Because the tag has a pre-release
suffix, the release is published as a GitHub pre-release and not marked
latest. A failed build or verification leaves a draft.

## Compatibility notes since v1.3.0-alpha.1

- **Schema.** Upgrading from `v1.3.0-alpha.1` applies the installer's schema
  steps from 1.2.36 to 1.2.39, including the opt-in asset register tables.
  Back up the database and RRD files first. Rollback means restoring that
  backup; replacing application files alone does not roll the database back
  (`docs/testing/release-rehearsal.md`).
- **Command-line scripts.** Twenty `cli/*.php` scripts now run through Symfony
  Console commands. They keep their arguments, output and exit codes, but they
  run as an operator account (`--as=<username>`, or the `admin_user` setting)
  that must be enabled, unlocked and hold Console Access plus the realm the
  matching web page needs. Check cron entries that run them under an account
  without those realms (`docs/migrations/cli-symfony-console.md`).
- **Web Basic authentication.** Auth method 2 takes the user only from
  `REMOTE_USER` or `REDIRECT_REMOTE_USER`. A web server that passes only
  `PHP_AUTH_USER` must now pass `REMOTE_USER`.
- **Migrated pages.** More administration pages render through Symfony and
  Twig. Old edit links redirect, and an edit form left open across the upgrade
  answers 409 instead of saving; reload it.
- **Windows.** RRDtool one-shot commands need writable temporary storage.
- **Carried over from v1.3.0-alpha.1.** Configured data-input whitelists need
  valid approvals before collection, and browser plugins must support jQuery 4.

## Known issues

These are open on main and not fixed in this preview:

- Installer: an incomplete schema is not refused (#1088); the Composer
  platform check hides missing PHP extensions (#1086); a cleared Scan Mode and
  stale CSRF tokens (#1116); a false failure in batch mode (#1071); handoff and
  installer workers do not retry a deadlock (#1438).
- main lacks some fixes that `lts/1.2` has (#1079).
- Further open bugs and hardening items are tracked in the issue tracker.
  Evaluate only against disposable data.

## Consumer verification

```sh
gh release download v0.1.0-alpha.1 --repo kadupulhq/kadupul \
  --pattern 'kadupul-offline.tar.gz*'
sha256sum --check kadupul-offline.tar.gz.sha256
gh attestation verify kadupul-offline.tar.gz --repo kadupulhq/kadupul \
  --bundle kadupul-offline.tar.gz.sigstore.json \
  --signer-workflow kadupulhq/kadupul/.github/workflows/release.yml
gh attestation verify oci://ghcr.io/kadupulhq/kadupul:0.1.0-alpha.1 \
  --repo kadupulhq/kadupul \
  --signer-workflow kadupulhq/.github/.github/workflows/release.yml
```

A matching checksum alone does not authenticate the release. Keep the
successful verification output and download the source/archive only from the
canonical repository. Evaluate against disposable data; see the documented
upgrade and rollback fixture limits in `docs/testing/release-rehearsal.md`.

After publication, rerun the main Scorecard publishing workflow and verify its
source revision, and add a note to the `v1.3.0-alpha.1` release that the 0.x
series supersedes it.
