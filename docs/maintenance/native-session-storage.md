# Native session storage maintenance

The LTS backport retains the native callback names, SessionHandlerInterface registration, supported PHP serializers and existing session table. New helper classes use PHP 8.1-compatible APIs and explicitly supplied PDO/context dependencies. They load before Composer where native bootstrap requires it. No Symfony module, schema version or dependency upgrade is introduced.

The byte-framing helper retains ordinary session values and references without constructing payload objects. Storage checks use the actual selected PDO/schema, persistent transactional participants, bounded display metadata and exact readback. Caller-owned transaction work is preserved; an initial owned savepoint failure is cleaned up before any callback work, while later/replacement transaction cleanup remains marker-bound. A false client-address sentinel retains empty display metadata without changing the authoritative address producer.

The explicit write-confirmation API reports only this backend's completed durability outcome and selected PDO identity. It performs no additional I/O and does not verify a later schema change. A callback staged inside a caller-owned transaction is not independently committed or confirmed by the helper. Existing column preparation remains available; no additional columns are required. File sessions and authentication/remember-me rules are unchanged.

Compatibility tests retain the existing session regression directory and use the branch's Pest 1 / PHPUnit 9 runner on PHP 8.1.34. New native cases execute the real serializer, callbacks and installation DDL in exclusively owned random schemas. Retained logout/activity tests use the production helper boundary, and the web registration fixture identifies its actual selected schema. HTTP child fixtures receive already-resolved administrative credentials, including explicit empty passwords. The lifecycle fixture requires 56 completed checks and the transaction-fault fixture requires 73, including borrowed/retry controls.

Local results and exact source hashes are exported separately for review. They are not a release, hosted-CI or whole-application acceptance claim. Deploy all four runtime files together. Rollback restores the earlier callbacks; existing stored session bytes and database schema do not require conversion. No real device or production collector is contacted by these tests.
