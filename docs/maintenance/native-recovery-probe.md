# Native collector queue-probe availability

Classification: main migration-related availability regression. The shared authenticated handoff enables `KADUPUL_THROW_DATABASE_ERRORS` before native bootstrap. `include/global.php` used throwing legacy database wrappers for read-only queue health, so an unreadable queue aborted bootstrap before its documented recovery fallback. It did not select an unauthorized primary; it refused the local workflow.

The correction checks only the two fixed queue queries on the actual local PDO. Confirmed empty queues permit online selection; pending, failed, unknown or unconfirmed reads retain recovery. The helper does not begin, commit, roll back, reconnect or alter the connection's error policy. Only PDO availability errors from these reads are handled. Programming errors still escape. Authentication and writes continue using the existing throwing wrappers.

The inspected LTS source (`origin/lts/1.2` at eaaa058a8980e9186a665098af26984e4c26f5d6) has no `KADUPUL_THROW_DATABASE_ERRORS` definition or caller, so this specific interaction is main-only. Its older ordinary-output recovery/drain gap remains a separate coherent backport concern tracked with #759; this correction does not claim that LTS recovery is otherwise correct. No architectural helper is backported solely for this main regression.

Before evidence: actual complete native bootstrap with distinct local/primary schemas fails for each unreadable queue at the legacy throwing database wrapper before callback execution. Healthy online, offline and both pending-queue controls pass. After evidence: the same native receiver web/worker flows pass all six modes, keep receiver writes in the selected schema, and demonstrate database sessions online and file-session fallback otherwise.
